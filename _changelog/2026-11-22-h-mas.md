# H-MAS Iteration 49 작업 노트

이번 Iteration 49 기간(11월 15일 ~ 11월 21일) 작업 내용을 안내합니다. 이번 작업에는 10개 커밋, 10개 PR이 포함되어 있습니다. v0.10 개발 주기 8주차입니다.

하이라이트는 다음과 같습니다:

- GPU를 여러 배포가 나눠 쓸 때 적용되는 메모리 격리가 노드를 재부팅하면 자동으로 적용되지 않던 문제를 해결했습니다. 그동안은 재부팅할 때마다 운영자가 직접 복구해야 했고, 복구를 놓치면 한 배포가 GPU 메모리를 과하게 차지할 수 있었습니다. 원인을 끝까지 추적해 H-MAS의 독자적인 노드 기동 순서 보정 기법으로 해결했고, 실제 클러스터를 재부팅해 사람 손 없이 격리가 다시 적용되는 것을 확인했습니다.
- 벤치마크 결과에서 GPU 활용도 값이 비어 있을 때 그 이유를 함께 보여 줍니다. GPU를 다른 배포와 함께 써서 측정 대상이 아닌 경우와, GPU 지표 수집에 이상이 있어 운영자 확인이 필요한 경우를 구분합니다. 측정을 시작하기 직전에 수집 상태를 점검해 문제가 있으면 실행 중에 바로 경고합니다. 지금까지는 수집이 멈춘 상태로 측정해도 결과가 정상처럼 보였습니다. 수집 상태는 CSV 내보내기에도 포함됩니다.
- 서빙 벤치마크를 SGLang 런타임, GPU 공유 배포, 여러 실행이 몰릴 때의 대기열까지 실제 클러스터에서 실측해 모든 실행 경로가 설계대로 동작하는 것을 확인했습니다. SGLang 배포는 첫 요청부터 지연 없이 응답했습니다.
- GPU 공유 환경의 성능 영향을 반복 측정했습니다. 같은 GPU의 다른 배포가 부하를 받으면 처리량이 약 50~54% 줄고, 이 결과는 반복 측정에서 ±1% 안으로 안정적이었습니다. 다른 배포가 쉬고 있을 때도 동시 요청이 많은 구간에서는 처리량이 약 20% 줄고 첫 토큰 지연이 크게 늘어, 공유 배치를 정할 때 동시 요청 수를 함께 고려해야 한다는 근거를 얻었습니다.
- 지금까지의 벤치마크 실측 결과를 주장별 근거 색인으로 정리하고 원자료를 함께 보존했습니다. 각 수치가 몇 번의 측정에 기반하는지, 얼마나 확실한지, 외부에 인용해도 되는지를 한눈에 확인할 수 있어 기술 자료와 논문에서 바로 인용할 수 있습니다.
- 배포 고급 설정의 추가 실행 인자를 특정 형태로 입력하면 등록되지 않은 모델이 실행될 수 있던 경로를 막았습니다. GPU 공유 배포의 메모리 격리 설정이 입력 형태에 따라 빠질 수 있던 경우도 함께 보완했습니다.
- 지원 런타임을 vLLM·SGLang 기준으로 정리했습니다. 모델 등록 화면에 실제로 배포할 수 없는 런타임이 선택지로 나오던 것을 없앴고, 소개자료와 블로그의 지원 런타임 문구도 현재 기준으로 맞췄습니다.
- 그 외 기존 테스트 전체를 점검해 품질 보강 과제를 정리하고, 3주째 실패하던 보안 정적 분석 주간 점검을 정상화했습니다.
